# 修复手册：按性价比排序

诊断脚本给出的每一项发现，都对应下面的杠杆。按顺序做，先做便宜且影响大的。

## 1. 先确认「谁在烧钱」

- 对照供应商后台（请求数 × 平均 token）与本地计量账本。
- 若本地账本几乎没有记录、供应商后台数额巨大 → 真实消耗来自账本之外的路径（底层 Agent 自身 / 另一台机器 / 共用同一 key 的其他程序）。先停掉或收紧那个客户端再谈优化，否则改了也白改。

## 2. 模型档位（通常是最大杠杆）

- 把默认模型从最贵档换到更轻的档（在上下文窗口相同的前提下）。
- 复杂任务按需临时切回强档，而不是全局常驻强档。

## 3. 推理强度

- high/xhigh → low：直接砍掉每轮的 reasoning 输出 token；仅对难题临时调高。

## 4. 上下文治理

- 设单会话软上限（建议 = 窗口的 10%）；接近即 compact，到自然边界就归档开新会话。
- 不要整目录 dump；用 rg 定位 + 限定行范围。
- 缓存占比 >90% 说明大部分 token 是「每轮重发上下文」，治本靠压缩会话长度，不靠换模型。

## 5. 子 Agent 默认

- 给 spawned agents 显式设轻档模型 + low 推理，避免继承父会话的最贵档。

## 6. 重试收敛

- 仅对瞬时错误（429/5xx/超时）重试；认证/策略/预算错误不重试；限制次数；避免原样重发大 prompt。

## 7. 计量闭环 + 对账

- 把 provider 返回的 usage 回写本地账本；初始化预算表并 seed 有依据的限额。
- 每天导出供应商 usage，对照当天会话；差值必须能解释。

## 8. 固定开销

- 关闭不用的插件 / MCP / 技能（每个都会把工具 schema 塞进每次请求）。
- 关闭不必要的高分辨率图片输入。

## Config 示例（Codex）

```toml
model = "<cheaper-model>"
model_reasoning_effort = "low"

[agents]
default_subagent_model = "<cheaper-model>"
default_subagent_reasoning_effort = "low"
```

## 安全

- 改配置前先备份；不回写密钥；估算成本 ≠ 真实账单；不在未授权时改生产配置或调用真实模型。
